## 一、Trae 核心架构解析

### 1.1 产品定位与版本体系

Trae 是字节跳动推出的 AI 原生集成开发环境，包含两个主要版本：

| 版本 | 定位 | 适用场景 |
|------|------|----------|
| TRAE IDE | AI 编程助手 | 专业开发者日常编码、复杂项目开发 |
| TRAE SOLO | AI 原生工作台 | 从需求到部署的全流程自动化开发 |

Trae 的核心理念是"Ship Faster with TRAE, More Than Coding"，强调 AI 贯穿软件开发全流程。

### 1.2 三大核心架构

Trae 的智能体系统由三大核心组件构成：


### 1.3 Plan + Agent 架构详解

TRAE SOLO 采用了"Plan（计划）+ Sub Agent（子智能体）"的架构设计，解决传统 AI 编程的三大痛点：

| 痛点 | 传统 AI IDE | TRAE SOLO 解决方案 |
|------|------------|-------------------|
| 缺乏全局观 | 只改一处，忽略关联 | Planning Agent 生成完整开发计划 |
| 上下文污染 | 长对话导致失忆 | Sub Agent 独立上下文，并行执行 |
| 黑盒操作 | 无法预判修改思路 | Human-in-the-loop，计划可修改 |

架构流程：

```
用户输入需求
    ↓
Planning Agent 分析代码库 → 生成开发计划文档 (Plan)
    ↓
Human Review (人工审核) → 开发者查看、修改、确认计划
    ↓
Sub Agents 集群并行执行
    ├── 前端 Agent 改 UI
    ├── 后端 Agent 改接口
    └── 测试 Agent 写 Case
    ↓
Execution → 写入代码 → DiffView 展示变更
```

## 二、模式选择与使用场景

### 2.1 三种模式对比

| 维度 | Chat 模式 | Builder 模式 | SOLO 模式 |
|------|-----------|--------------|-----------|
| 核心定位 | AI 编程辅助助手 | 代码项目生成工具 | 全流程自主开发的智能体 |
| 主导权 | 你主导，AI 辅助 | 你提需求，AI 生成 | AI 主导执行，你做决策者 |
| 交互方式 | 问答式、内联补全 | 一句话生成完整项目 | 多轮对话+AI自主执行 |
| 自主能力 | 低，每次需要明确指令 | 中，生成后需手动调试 | 高，自主规划、编码、调试、验证 |
| 适用场景 | 修改代码、解读逻辑、修 Bug | 从零快速出 MVP 原型 | 复杂项目全流程开发、迭代、重构 |

简单理解：

- **Chat 模式**："我帮你写"
- **Builder 模式**："我帮你搭"
- **SOLO 模式**："我替你干"

### 2.2 SOLO 模式子组件

SOLO 不是单一大 AI 在干活，而是一个多智能体协作系统：

| 组件 | 职责 | 适用场景 |
|------|------|----------|
| SOLO Builder | 从 0 到 1 的完整项目搭建 | 快速验证创意、搭建应用原型 |
| SOLO Coder | 从 1 到 100 的复杂项目迭代 | 功能迭代、架构重构、Bug 修复 |
| SubAgent | 复杂任务分解并行执行 | 跨模块大型项目 |

### 2.3 Plan 模式与 Spec 模式

SOLO Coder 内置两种任务规划机制：

#### Plan 模式：先计划，再动手

适合中小型功能开发和模块级重构。启用后，AI 先生成详细开发清单，包含：

- 需要改动的文件列表
- 具体执行步骤
- 潜在风险点

**核心优势**：计划可以手动编辑，只有确认后才执行代码。

```
输入: /plan
AI 生成计划:
1. 修改 src/models/User.ts
2. 更新 DTO 定义
3. 修改前端 TypeScript 类型
4. 添加数据库迁移脚本

你审核后修改:
- 在第2步增加 DTO 验证逻辑

点击确认 → AI 开始执行
```

#### Spec 模式：系统级工程管理

面向复杂的系统级任务，生成三份标准化文档：

| 文档 | 内容 | 存储位置 |
|------|------|----------|
| spec.md | 项目背景、整体架构、技术选型 | .trae/specs/ |
| tasks.md | 细粒度可执行任务列表 | .trae/specs/ |
| checklist.md | 验收对照表 | .trae/specs/ |

**适用场景**：

- 从零搭建新系统/模块
- 大规模重构
- 多人协作项目
- 高质量/高稳定性项目
- 需长期维护的项目

## 三、高级使用技巧

### 3.1 对话式编程核心技巧

#### 三大上下文注入符

在对话框输入 `@` 会弹出上下文选择：

| 符号 | 功能 | 使用场景 |
|------|------|----------|
| @file | 引用完整文件内容 | 精准修改特定文件 |
| @folder | 注入整个文件夹概述 | 让 AI 了解项目结构 |
| @terminal | 终端最近输出作为上下文 | 直接给 AI 看错误日志 |

**实战示例**：

```bash
# ❌ 错误做法
"在 Home 页面加上获取用户列表的请求"
# → AI 可能会写裸 fetch 或发明不存在的函数

# ✅ 正确做法
@file src/pages/Home.tsx @file src/services/api.ts
请基于 api.ts 中已有的 request.get 方法，在 Home 页面组件中增加获取用户列表的逻辑，并处理 loading 和 error 状态。
# → AI 会严格使用项目已有的请求封装
```

#### 最小上下文原则

- 一次最多引入 2-3 个直接相关文件
- 外加一个顶级文件夹结构就够了
- 上下文太大，AI 注意力会被稀释

### 3.2 分步征服复杂需求

#### 骨架先行法

```
需求: 实现用户注册与登录模块

# 第一步：先要结构
"请列出实现这个模块需要的全部文件路径和函数签名，
包括所需参数和返回值，不需要写具体实现。
使用 TypeScript + Express，项目结构遵循现有的
src/models、src/routes、src/controllers 分层。"

# AI 输出结构表后，核对确认

# 第二步：逐步实现
"现在开始实现 src/models/User.ts，先给出完整的
model 定义和验证函数。"
```

#### 修改-验证闭环

```bash
@terminal 刚才的注册接口返回 422 错误，日志显示
password too short，请修正 validateUserInput 中的
密码最小长度，并更新相关测试。
```

### 3.3 代码风格统一技巧

#### 利用 # 引用已有符号

```bash
请仿照 #ProductList 组件的 props 接口、样式结构和
加载状态处理方式，实现一个 #OrderList 组件。
```

#### 风格植入法

拖一个写得好的文件到对话框，说：

```
以下代码是我的风格基准，之后所有新增代码务必严格
模仿这个文件的缩进、命名习惯、注释密度以及
async/await 使用模式。
```

#### 全局用户规则

在 `设置 → User Rules` 中填写全局规则：

```
- 所有 TypeScript 文件使用 2 空格缩进，单引号，无分号
- 组件必须显式声明返回类型
- API 调用统一通过 `src/utils/request.ts` 导出
```

### 3.4 跨文件逻辑修改

**实例**：把用户信息格式从 `{ name, avatar }` 改为 `{ nickname, role }`

```bash
# 第一步：让 AI 自动搜出所有引用点
@folder src 搜索整个 src 目录，列出所有使用了
name 和 avatar 的用户对象读取代码段，文件数量不限。

# 第二步：一次性批量修改
请将上述所有位置的 name 改为 nickname，并新增
role 字段的展示逻辑。

# 第三步：检验一致性
@terminal 执行前端类型检查命令
```

### 3.5 对话编程微操技巧清单（18条精选）

| 技巧 | 说明 | 示例 |
|------|------|------|
| 分界符防污染 | 多任务用 `--- 新任务 ---` 隔开 | 分隔不同子任务 |

| 错误回滚 | 本地历史或 Git 回滚 | 不怕改崩 |

## 四、Skills 与 MCP 高级应用

### 4.1 Skills 核心概念

**Skills** 本质上是给 AI 定制的"工作手册"，包含工作要求、格式规范、执行流程。

```
Skills 核心价值：
├── MCP 管"连接"（打通 AI 与外部工具）
├── Skill 管"规范"（明确调用时机、参数、流程）
└── SOLO 多Agent 管"调度"（分配任务、协同执行）
```

### 4.2 MCP 与 Skill 绑定实战

#### 飞书文档 MCP 示例

```python
# 飞书文档 MCP 与 Skill 绑定配置
office_auto_skill = {
    "skill_name": "office_auto_skill",
    "bind_mcp": "feishu_doc_mcp",
    "trigger_keywords": ["飞书文档", "报告生成", "文档提取"],
    "mcp_config": {
        "mcp_url": "https://open.feishu.cn/open-apis/mcp/v1/",
        "auth_info": {
            "app_id": "your_app_id",
            "app_secret": "your_app_secret"
        },
        "required_params": ["doc_id", "operation_type", "output_format"]
    },
    "call_logic": lambda params: requests.post(
        url=f"{office_auto_skill['mcp_config']['mcp_url']}operate",
        json={**params, **office_auto_skill['mcp_config']['auth_info']}
    ).json()
}
```

#### GitHub MCP 示例


### 4.3 多 Agent 协同调用模式

#### 三步走通用逻辑

```
1. 归纳绑定：将同类 MCP 服务归纳到对应 Skill 中
2. 任务拆分：将复杂任务拆分为单一原子任务
3. 结果联动：每个 Agent 调用后的结果同步到上下文
```

#### 多 Agent 协同调用示例

```python
from trae_solo.agent import SchedulerAgent, ExecutorAgent

# 初始化 Agent
scheduler = SchedulerAgent()
executor1 = ExecutorAgent(skill="office_auto_skill")  # 提取数据
executor2 = ExecutorAgent(skill="office_auto_skill")  # 生成简报
executor3 = ExecutorAgent(skill="office_auto_skill")  # 发送群聊

# 调度 Agent 拆分任务
task = "自动提取飞书文档中上月销售数据，生成经营分析简报"
sub_tasks = scheduler.split_task(task, ["extract_data", "generate_report", "send_group"])

# 执行 Agent 1: 提取数据
extract_params = {
    "doc_id": "doc-xxxxxx",
    "operation_type": "extract",
    "output_format": "json"
}
sales_data = executor1.call_skill(params=extract_params)

# 执行 Agent 2: 生成简报
report_params = {
    "doc_id": "new-doc-xxxxxx",
    "operation_type": "create",
    "content": f"### 上月经营简报\n{sales_data}"
}
report_url = executor2.call_skill(params=report_params)["share_url"]

# 执行 Agent 3: 发送到群
send_params = {
    "operation_type": "share",
    "group_id": "group-xxxxxx",
    "share_url": report_url
}
executor3.call_skill(params=send_params)
```

## 五、最优方案与最佳实践

### 5.1 项目级最优方案

#### 企业级多 Agent 协作架构

```
┌─────────────────────────────────────────────────────────────┐
│                  SOLO Coder (总指挥)                        │
│  • 拆解需求 → 分配任务 → 管控流程 → 校验成果                │
└─────────────────────────────────────────────────────────────┘
                            ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│                    SKILL MCP (公共底座)                     │
│  • 统一存储：架构文档、设计图纸、代码、测试报告              │
│  • 共享技能：语法校验、组件库、测试脚本                     │
│  • 互训数据：协作经验、问题整改记录                         │
└─────────────────────────────────────────────────────────────┘
                            ↓ ↑
┌─────────────────────────────────────────────────────────────┐
│  架构Agent  │  设计Agent  │  研发Agent  │  测试Agent      │
│  • 定骨架   │  • 定样式   │  • 写代码   │  • 测bug       │
│  • 定规则   │  • 定标准   │  • 做联调   │  • 做回归       │
└─────────────────────────────────────────────────────────────┘
```

#### 各阶段任务分配

| 阶段 | Agent | 输出物 |
|------|-------|--------|
| 需求分析 | 架构Agent | spec.md、模块拆分、接口规范 |
| UI设计 | 设计Agent | 视觉稿、交互规范、样式标准 |
| 编码开发 | 研发Agent | 业务代码、前后端接口 |
| 测试验收 | 测试Agent | 测试报告、bug列表、回归测试 |

### 5.2 开发流程最佳实践

#### SOLO 模式标准工作流

```
1. 需求输入
   └── 清晰描述最终目标

2. Plan/Spec 审核
   └── AI 生成计划 → 你审核修改 → 确认执行

3. 多 Agent 并行开发
   └── 架构 → 设计 → 研发 → 测试

4. DiffView 代码审查
   └── 逐文件审核变更 → 接受/拒绝

5. 验证与交付
   └── AI 自主验证 → 浏览器测试 → 修复问题

6. 部署
   └── Vercel 一键部署
```

#### 任务拆分原则

- 大项目拆成多个可独立推进的子模块
- 每个模块可独立运行和验证
- 避免一次性交付过多内容
- 定期检查进度，遇到偏航及时纠正

### 5.4 避坑指南

#### 安全铁律

| 场景 | 风险 | 应对 |
|------|------|------|
| 删除代码 | 数据丢失 | 务必审核 diff |
| 数据库变更 | 数据损坏 | 人工确认 |
| 第三方配置 | 服务中断 | 理解每条变更 |
| 危险操作 | 系统破坏 | 手动审计 |

#### 常见问题解决

| 问题 | 原因 | 方案 |
|------|------|------|
| AI 无响应 | 网络/上下文过长 | 检查网络/精简上下文 |
| 建议不合理 | 缺少约束 | 添加具体约束条件 |
| 代码不生成 | Token 溢出 | 开启新对话或压缩上下文 |
| 上下文污染 | 长对话失焦 | 使用上下文压缩功能 |

## 六、学习路径与资源

### 6.1 分阶段学习路径

#### 第一阶段：基础入门（1-2天）

1. 安装 Trae（官网下载）
2. 完成初始设置（添加命令行、登录）
3. 熟悉界面和基础功能（Chat/Builder 模式）

## 七、隐私与安全

### 7.1 数据隐私保护

- 代码库文件存储在本地
- 索引文件临时上传，处理后删除明文
- 支持隐私模式和忽略功能

### 7.2 安全访问控制

- 严格的访问控制和加密传输
- 用户数据存储在美国、新加坡、马来西亚

### 7.3 最佳安全实践

```
⚠️ 禁止在对话中输入：
├── API 密钥、Token
├── 数据库密码
├── 用户隐私信息
└── 商业机密

✅ 正确做法：
1. 使用环境变量
2. 使用密钥管理服务
3. 在对话中只描述结构，不暴露值
```

## 八、总结

### 核心要点

```
1. Trae 是 AI Native IDE，AI 贯穿开发全流程
2. 三种模式：Chat（帮你写）、Builder（帮你搭）、SOLO（替你干）
3. SOLO 的 Plan + Agent 架构解决 AI 编程失控问题
4. Skills + MCP 实现外部工具标准化连接
5. 多 Agent 协作可组建 AI 研发团队
6. 安全第一：审核 diff、谨慎操作、保护敏感信息
```

### 核心理念

> AI 不是替代程序员，而是增强程序员的能力。学会与 AI 协作，才能在 AI 时代保持竞争力。
